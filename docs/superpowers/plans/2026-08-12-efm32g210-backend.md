# EFM32G210F128 Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third Data Vault platform backend, `efm32g210`, targeting the Silicon Labs EFM32G210F128 (Cortex-M3, QFN32) on the Olimex EM-32G210F128-H board, implementing the same `vault/platform.h` HAL contract the `lpc810` and `stm32u031` backends already satisfy. `core/` is unmodified by this plan except where noted (Task 5 depends on `platform_wait_for_interrupt()`, already added to `vault/platform.h` and both existing backends).

**Architecture:** Same three-layer pattern as the existing backends: `core/` (unchanged), `platform.h` (unchanged — this backend implements the existing contract, no new functions needed beyond what LPC810/STM32U031 already added), and a new `platform/efm32g210` backend using Silicon Labs' **emlib** vendor peripheral library (per design decision — matches the STM32U031 backend's HAL-based abstraction level, not the LPC810 backend's bare-register style).

**Tech Stack:** C11, CMake 3.20+, `arm-none-eabi-gcc -mcpu=cortex-m3`, Silicon Labs Gecko SDK (CMSIS device header + emlib) vendored via git submodule.

## Global Constraints

- `VAULT_CONTEXT_SIZE`: 320 bytes, matching both existing hardware backends (RadioLib's real persisted-state requirement — see the design spec's rationale). Trivial against this part's 16 KB RAM.
- `VAULT_I2C_ADDR`: `0x42` (7-bit), unchanged.
- `VAULT_DEFAULT_WAKE_INTERVAL_SEC`: 60, unchanged.
- Board pin assignments (confirmed against the Olimex EM-32G210F128-H user manual's own schematic — see `docs/superpowers/specs/2026-08-12-efm32g210-backend-design.md` §2 — not assumed):
  - `MAIN_RAIL_EN`: `PC13`
  - I2C0 SDA/SCL: `PD6`/`PD7`
  - Debug UART TX: `PC0` (USART1)
  - LFXO (32.768 kHz, RTC clock): `PB7`/`PB8` — already populated on-board
  - HFXO (32 MHz, main clock): `PB13`/`PB14` — already populated on-board
- Flash: 128 KB at `0x00000000`. RAM: 16 KB at `0x20000000` (confirmed from the board manual's own memory map, not assumed).
- Sleep mode: EM2 (Deep Sleep) — see spec §5 for the EM2-vs-EM3 rationale (EM3 cannot wake from the RTC on this chip).
- No git commit includes a "Co-Authored-By" trailer (repo-wide rule).
- Every register/emlib-API detail flagged "verify against reference manual" below is a real open question, not decorative caution — confirm it against the vendored header/reference manual before flashing, the same discipline the LPC810 and STM32U031 backends' own code comments already apply throughout this codebase.

- [ ] **Step 3: Create the linker script**

`platform/efm32g210/linker/efm32g210f128.ld` (128 KB flash at `0x00000000`, 16 KB RAM at `0x20000000` — confirmed from the board manual's own memory map):

```ld
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x00000000, LENGTH = 128K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 16K
}

ENTRY(Reset_Handler)

SECTIONS
{
    .isr_vector :
    {
        KEEP(*(.isr_vector))
    } > FLASH

    .text :
    {
        *(.text*)
        *(.rodata*)
        . = ALIGN(4);
    } > FLASH

    _sidata = LOADADDR(.data);

    .data :
    {
        _sdata = .;
        *(.data*)
        _edata = .;
    } > RAM AT> FLASH

    .bss :
    {
        _sbss = .;
        *(.bss*)
        *(COMMON)
        _ebss = .;
    } > RAM

    ._user_heap_stack :
    {
        . = ALIGN(8);
        . = . + 1024;
        . = ALIGN(8);
    } > RAM

    _estack = ORIGIN(RAM) + LENGTH(RAM);
}
```

Note the `. = ALIGN(4);` before `_sidata = LOADADDR(.data);` is included from the start this time — both other backends in this repo hit a real bug from omitting this (LPC810: caused a HardFault; STM32U031: fixed proactively after the LPC810 lesson) — do not repeat that omission on a third backend.

`platform/efm32g210/src/platform_efm32g210_gpio.c`:
```c
#include "vault/platform.h"
#include "em_cmu.h"
#include "em_gpio.h"

#define MAIN_RAIL_EN_PORT gpioPortC
#define MAIN_RAIL_EN_PIN  13
#define I2C_SDA_PORT      gpioPortD
#define I2C_SDA_PIN       6
#define I2C_SCL_PORT      gpioPortD
#define I2C_SCL_PIN       7

void efm32g210_gpio_init(void) {
    CMU_ClockEnable(cmuClock_GPIO, true);

    GPIO_PinModeSet(MAIN_RAIL_EN_PORT, MAIN_RAIL_EN_PIN, gpioModePushPull, 0);
}

void platform_main_rail_enable(bool on) {
    if (on) {
        GPIO_PinOutSet(MAIN_RAIL_EN_PORT, MAIN_RAIL_EN_PIN);
    } else {
        GPIO_PinOutClear(MAIN_RAIL_EN_PORT, MAIN_RAIL_EN_PIN);
    }
}

void platform_bus_isolate(void) {
    /* Disabled (high-impedance, no pull), the EFM32 equivalent of the
       analog/no-pull isolation state both other backends put SDA/SCL
       into before cutting the main MCU's rail (design spec's own
       parasitic-back-powering mitigation, spec section 5 of the
       original MCU analysis report). gpioModeDisabled is emlib's
       high-impedance input mode -- verify this is truly no-pull (not a
       weak pull-up/down default) against the reference manual's GPIO
       chapter before flashing. */
    GPIO_PinModeSet(I2C_SDA_PORT, I2C_SDA_PIN, gpioModeDisabled, 0);
    GPIO_PinModeSet(I2C_SCL_PORT, I2C_SCL_PIN, gpioModeDisabled, 0);
}
```

- [ ] **Step 1: Implement clock init and RTC wake timer**

`platform/efm32g210/src/platform_efm32g210.c`:
```c
#include "vault/platform.h"
#include "em_cmu.h"
#include "em_rtc.h"
#include "em_emu.h"

extern void efm32g210_gpio_init(void);

static void efm32g210_clock_init(void) {
    /* HFXO (32 MHz, already populated on-board per the Olimex schematic)
       as the main/core clock, matching this design's decision to use
       the populated crystals from the start rather than staging through
       an internal RC oscillator first (see the design spec's rationale
       for why this differs from the STM32U031 backend's LSE-vs-LSI
       history: this crystal is presumably already validated by Olimex's
       own demo firmware). Verify the exact CMU_OscillatorEnable()/
       CMU_ClockSelectSet() call signatures against the vendored em_cmu.h
       -- API shape may differ slightly by emlib version. */
    CMU_OscillatorEnable(cmuOsc_HFXO, true, true);
    CMU_ClockSelectSet(cmuClock_HF, cmuSelect_HFXO);

    /* LFXO (32.768 kHz, already populated) feeds the RTC via the LFA
       clock branch -- verify cmuClock_LFA is the correct branch name
       for RTC specifically on this part (some EFM32 generations route
       RTC via a differently-named branch) against the reference
       manual's Clock Management Unit chapter. */
    CMU_OscillatorEnable(cmuOsc_LFXO, true, true);
    CMU_ClockSelectSet(cmuClock_LFA, cmuSelect_LFXO);
    CMU_ClockEnable(cmuClock_RTC, true);
}

static void efm32g210_rtc_init(void) {
    RTC_Init_TypeDef rtc_init = RTC_INIT_DEFAULT;
    rtc_init.enable = false; /* enabled explicitly on first arm, not here */
    rtc_init.comp0Top = false; /* free-running counter, not comp0-reset --
                                   verify against em_rtc.h whether this
                                   default is what platform_wakeup_timer_arm()
                                   below actually needs, or whether
                                   comp0Top=true (auto-reset on compare
                                   match) is the correct choice instead */
    RTC_Init(&rtc_init);

    NVIC_EnableIRQ(RTC_IRQn);
}

void platform_init(void) {
    efm32g210_gpio_init();
    efm32g210_clock_init();
    efm32g210_rtc_init();
}

void platform_wakeup_timer_arm(uint32_t seconds) {
    /* RTC counts at the 32.768 kHz LFXO rate -- reload/compare value ==
       seconds * 32768, assuming no additional prescaler is active.
       Verify against em_rtc.h / the reference manual whether this part's
       RTC has a mandatory or configurable prescaler that would change
       this arithmetic (unlike the STM32U031 backend's RTC, which
       deliberately divides down to a clean 1 Hz SPRE clock via its own
       prediv registers -- this EFM32 RTC may or may not have an
       equivalent, verify before trusting this multiply). */
    RTC_CompareSet(0, seconds * 32768u);
    RTC_IntEnable(RTC_IEN_COMP0);
    RTC_Enable(true);
}

void platform_wakeup_timer_clear(void) {
    RTC_IntClear(RTC_IFC_COMP0);
}

void RTC_IRQHandler(void) {
    platform_wakeup_timer_clear();
}
```

### Task 5: I2C0 slave driver

**Files:**
- Create: `platform/efm32g210/src/platform_efm32g210_i2c.c`
- Modify: `platform/efm32g210/CMakeLists.txt`

**Interfaces:**
- Consumes: `vault_i2c_registers_on_write_byte`, `vault_i2c_registers_on_read_request`, `vault_i2c_registers_on_stop` (`core/`, same functions both other backends already drive).
- Produces: `platform_i2c_slave_init(uint8_t addr)`, `platform_i2c_slave_deinit(void)`, `platform_wait_for_interrupt(void)`, `I2C0_IRQHandler(void)`.

Per the design spec §6: emlib's `em_i2c.c` is written primarily for master-mode polled transfers, so expect this driver to sit closer to raw register access than the STM32 backend's HAL-callback-based I2C driver does — closer in spirit to how the LPC810 I2C0 driver already works entirely via direct register access. This is the second task (after Task 4's RTC) most in need of reference-manual cross-checking: the exact `I2C0->ROUTE` `LOCATION` field value for `PD6`/`PD7`, and the I2C peripheral's own slave-mode state/interrupt-flag layout, are both genuinely silicon-specific.

- [ ] **Step 1: Implement the I2C0 slave driver**

`platform/efm32g210/src/platform_efm32g210_i2c.c`:
```c
#include "vault/platform.h"
#include "vault/vault_i2c_registers.h"
#include "em_cmu.h"
#include "em_i2c.h"

/* I2C0 ROUTE LOCATION for PD6 (SDA)/PD7 (SCL) -- the board's own
   schematic labels these pins "I2C0_SDA"/"I2C0_SCL", strongly implying
   they're a valid alternate-location pair for this peripheral on this
   part, but the exact LOCATION index (I2C_ROUTE_LOCATION_LOCn) must be
   confirmed against the EFM32G210 reference manual's I2C0 alternate-
   function table before flashing -- do not guess this value. */
#define I2C0_ROUTE_LOCATION 0 /* Best-guess default location index;
                                     verify the real value against the
                                     EFM32G210 reference manual's I2C0
                                     alternate-function table before
                                     flashing -- see the caveat above. */

void platform_i2c_slave_init(uint8_t addr) {
    CMU_ClockEnable(cmuClock_I2C0, true);

    /* Pin routing + peripheral enable via ROUTE register -- verify the
       exact field names (I2C_ROUTE_SDAPEN, I2C_ROUTE_SCLPEN,
       I2C_ROUTE_LOCATION_LOCn) against the vendored efm32g210f128.h
       before flashing; this follows the general EFM32 ROUTE-register
       pattern but the exact macro names are part-specific. */
    I2C0->ROUTE = I2C_ROUTE_SDAPEN | I2C_ROUTE_SCLPEN | I2C0_ROUTE_LOCATION;

    /* Slave address in bits [7:1] -- verify field layout (I2C_SADDR
       register) against the reference manual's I2C chapter. */
    I2C0->SADDR = (uint32_t)(addr << 1);

    /* Enable the peripheral and its relevant interrupt sources (address
       match, RX data valid, TX buffer level, STOP condition -- exact
       IEN bit names must come from the vendored header, not be
       guessed). */
    I2C0->CTRL |= I2C_CTRL_EN;
    I2C0->IEN |= I2C_IEN_ADDR | I2C_IEN_RXDATAV | I2C_IEN_SSTOP;

    NVIC_EnableIRQ(I2C0_IRQn);
}

void platform_i2c_slave_deinit(void) {
    NVIC_DisableIRQ(I2C0_IRQn);
    I2C0->CTRL &= ~I2C_CTRL_EN;
    I2C0->ROUTE = 0;
    CMU_ClockEnable(cmuClock_I2C0, false);
}

void platform_wait_for_interrupt(void) {
    /* Plain WFI -- EFM32's EMU_EnterEM2()/EM3 entry points are separate
       emlib calls (em_emu.h) for the deeper sleep this function
       deliberately does NOT enter (see platform_enter_low_power_sleep()
       in platform_efm32g210.c, Task 6); this only needs to halt the CPU
       core clock until the I2C0 interrupt (already enabled above)
       fires, matching the plain-WFI implementations already added to
       the LPC810 and STM32U031 backends. */
    __WFI();
}

void I2C0_IRQHandler(void) {
    uint32_t flags = I2C0->IF;

    /* Exact flag names/decode order (address match vs. RX vs. TX vs.
       STOP) must be verified against the reference manual's I2C status
       register description -- this sketch assumes flags are
       independently testable bits, matching the general EFM32 I2C IF
       register convention, but the precise sequencing (e.g. whether
       ADDR must be acknowledged before RXDATAV can be serviced) needs
       confirming before flashing. */
    if (flags & I2C_IF_ADDR) {
        I2C0->IFC = I2C_IFC_ADDR;
    }
    if (flags & I2C_IF_RXDATAV) {
        vault_i2c_registers_on_write_byte((uint8_t)I2C0->RXDATA);
    }
    if (flags & I2C_IF_TXBL) {
        I2C0->TXDATA = vault_i2c_registers_on_read_request();
    }
    if (flags & I2C_IF_SSTOP) {
        I2C0->IFC = I2C_IFC_SSTOP;
        vault_i2c_registers_on_stop();
    }
}
```

/* TX-only debug UART on PC0 (USART1) -- matching the TX-only pattern
   both other backends already use (bring-up logging need is one-way).
   Board schematic labels PC0/PC1 "US1_TX"/"US1_RX". USART1 ROUTE

   manual before flashing -- same caveat as I2C0's LOCATION in Task 5. */

                                       reference manual's USART1
                                       alternate-function table before
                                       flashing -- see the caveat above. */

void efm32g210_uart_init(void) {
    CMU_ClockEnable(cmuClock_USART1, true);

    GPIO_PinModeSet(USART1_TX_PORT, USART1_TX_PIN, gpioModePushPull, 1);

    USART_InitAsync_TypeDef init = USART_INITASYNC_DEFAULT;
    init.baudrate = 57600; /* matches the fixed baud rate both other
                               backends already settled on */
    USART_InitAsync(USART1, &init);

    USART1->ROUTE = USART_ROUTE_TXPEN | USART1_ROUTE_LOCATION;
}

/* core/'s vault_log() contract (vault/vault_log.h). Only called from
   vault_core's normal thread-mode control flow, never from the I2C0
   ISR -- matching both other backends' convention (see the comment in

void vault_log(const char *msg) {
    while (*msg != '\0') {
        USART_Tx(USART1, (uint8_t)*msg);
        msg++;
    }
}
